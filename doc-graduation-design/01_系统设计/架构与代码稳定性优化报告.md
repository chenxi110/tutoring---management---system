## 一、优化背景

系统在长期运行中暴露以下稳定性问题，本次优化围绕"最不容易出错"的目标，从**异常处理、安全编码、日志规范、配置健壮性、部署脚本**五个维度进行系统性加固。**不新增业务功能、不改变数据库结构、不改变API接口契约、不改变前端布局。**

## 二、优化内容明细

### 1. 全局异常处理重写（GlobalExceptionHandler.java）

| 原状态 | 优化后 |
|--------|--------|
| 异常处理覆盖不全，部分异常直接抛到页面 | 重写全局异常处理器，覆盖8类常见异常 |
| 错误信息可能泄露内部细节 | 统一响应格式，友好提示 |

**新增异常处理器：**
- 数据库访问异常（DataAccessException）→ 返回"数据操作失败，请稍后重试"
- 参数缺失（MissingServletRequestParameterException）→ 明确提示缺失参数名
- 参数类型不匹配（MethodArgumentTypeMismatchException）→ 提示参数格式错误
- JSON解析异常（HttpMessageNotReadableException）→ 提示请求体格式错误
- 空指针异常（NullPointerException）→ 返回友好提示，防止500空白页
- 非法参数（IllegalArgumentException）→ 直接透传业务提示
- 权限异常（AccessDeniedException）→ 统一"无权限访问"
- 兜底Exception → 记录日志 + 统一"系统繁忙"

**效果：** 任何异常都返回统一JSON（code/msg/data），不再出现500空白页或Java堆栈暴露。

### 2. JWT安全修复（JwtUtil.java）

| 问题 | 修复 |
|------|------|
| `secret.getBytes()` 未指定UTF-8编码，跨平台/多字节字符场景可能产生不一致的密钥 | 改为 `secret.getBytes(StandardCharsets.UTF_8)`，保证所有平台生成一致的密钥 |
| `validateToken()` 对null token无防护 | 增加空值防护，null/空token直接返回false |

**效果：** 消除因编码问题导致的token校验偶发失败；空token不会触发NPE。

### 3. 认证服务健壮性（AuthService.java / AuthController.java）

- `login()` 增加空值防护 + try-catch，登录失败不会抛未处理异常
- `password_hash` 空值防护，防止空密码比较NPE
- 所有 `System.out.println` 替换为 SLF4J 日志（支持级别控制、日志文件、生产关闭）

**效果：** 登录逻辑更健壮，日志规范化可追溯。

### 4. 数据初始化容错（DataInitializer.java）

- 全部 `System.out` 替换为日志
- 外层增加 try-catch：**数据库不可用时不再导致应用启动失败**，降级为警告日志

**效果：** 提升启动稳定性，数据库短暂不可用时应用仍能启动（Web界面可访问）。

### 5. Service层全面加固（9个Service）

**涉及文件：**
- `GradeService.java` / `GradeController.java`
- `AIService.java` / `AnalysisService.java`
- `FinanceService.java` / `EvaluationService.java`
- `WrongQuestionService.java` / `ExamService.java`
- `DataPortService.java` / `MessageService.java`
- `CourseFileService.java`

**优化内容：**
| 优化项 | 说明 |
|--------|------|
| 空catch块全部补日志 | 消除"吞异常"导致的静默失败，问题可追踪 |
| `printStackTrace()` 替换为日志 | 不再向控制台堆栈，统一走日志框架 |
| `GradeService.batchCreate()` 加 `@Transactional` | 批量导入成绩保证事务性，全部成功或全部回滚 |
| `CourseFileService` 随机数优化 | `new Random()` → `ThreadLocalRandom`，消除并发竞争 |

**效果：** 消除静默失败、并发隐患，批量数据操作具备事务保障。

### 6. 配置统一与生产就绪（application.yml）

**新增配置：**
| 配置项 | 作用 |
|--------|------|
| 优雅关闭（shutdown: graceful） | 应用停止时等待请求处理完成，不粗暴kill |
| HikariCP连接池参数 | 连接池大小、超时、泄漏检测，数据库连接更稳定 |
| 日志文件输出 | 应用日志写入文件，便于排查 |
| 环境变量覆盖 | 数据库地址/账号等支持环境变量注入，适配Zeabur部署 |

**效果：** 生产部署配置完整，日志可查，连接管理优化。

### 7. 启动/停止脚本（start.bat / stop.bat）

- `start.bat`：启动应用（含JVM参数、端口检查、启动日志）
- `stop.bat`：优雅停止应用（按PID关闭，不残留进程）

**效果：** 一键启动/停止，避免手动操作失误。
