## 0. 可行性分析

### 0.1 技术可行性

本系统采用成熟的主流技术栈，技术风险可控：

- **后端技术**：Spring Boot 3.x + Java 17，企业级开发框架，生态完善，社区活跃，学习资源丰富
- **数据库**：MySQL 8.0，关系型数据库，支持事务、索引、外键约束，满足教学管理数据的一致性和完整性要求
- **前端技术**：原生HTML/CSS/JavaScript + ECharts，无需复杂构建工具，部署简单，兼容性好
- **安全框架**：JWT Token鉴权 + RBAC角色权限模型，实现四级角色权责分离
- **开发工具**：IntelliJ IDEA + Maven + Git，标准化开发流程

以上技术均为当前企业级应用开发的主流选择，技术成熟度高，文档齐全，开发团队具备相关技术能力，技术可行性充分。

### 0.2 经济可行性

- **开发成本**：系统采用开源技术栈，无需购买商业软件授权，开发成本主要为人力成本
- **部署成本**：支持单机部署，普通PC服务器即可运行，无需高端硬件投入；也可部署于云服务器，月均成本低
- **运维成本**：系统提供自动化启动脚本、操作日志审计、全局异常处理，降低运维难度
- **收益分析**：系统可帮助辅导机构实现教学管理数字化，减少人工统计成本，提升家校沟通效率，具备实际应用价值

综合来看，系统开发和运维成本较低，而管理效益显著，经济可行性良好。

### 0.3 操作可行性

- **用户体验**：系统界面简洁直观，采用侧边栏导航+卡片式布局，符合常规管理系统操作习惯，用户学习成本低
- **角色适配**：四级角色（管理员/教师/家长/学生）界面差异化设计，各角色仅看到相关功能，避免信息过载
- **数据处理**：支持Excel批量导入导出，减少人工录入工作量；提供教学数据看板，直观展示关键指标
- **部署便捷**：提供一键启动脚本，双击即可运行；支持局域网访问，教室内多设备可同时使用
- **容错设计**：全局异常处理+友好提示，操作失败不崩溃；表单前后端双重校验，防止非法数据录入

系统操作简单，部署便捷，维护成本低，适合中小型辅导机构实际使用，操作可行性充分。

### 0.4 可行性结论

综合技术、经济、操作三个维度的分析，本系统开发技术成熟、成本可控、操作便捷，具备充分的可行性，可进入系统设计与开发阶段。

## 1. 需求分析

### 1.1 系统概述

"上课通"是一款面向课外辅导机构的教学辅助管理系统，旨在解决辅导机构在教学管理、家校沟通、成绩跟踪等方面的痛点，实现教学管理数字化、家校协同一体化、教学决策数据化。

### 1.2 角色定义

| 角色 | 权限范围 | 主要功能 |
|------|---------|---------|
| 超级管理员(admin) | 系统全局 | 班级创建、教师账号分配、系统参数设置、操作日志查看、用户管理 |
| 教师(teacher) | 所带班级 | 教学管理、成绩录入、作业发布批改、家校沟通、上课模式、考试管理 |
| 家长(parent) | 自家孩子 | 查看孩子成绩/作业/出勤、接收通知、与教师私信、上课模式参与 |

| 安全 | JWT身份认证、BCrypt密码加密、角色权限控制、操作审计日志 |

## 4. 详细设计

### 4.1 核心业务流程图

#### 4.1.1 作业批改闭环流程

```
教师发布作业
    │
    ▼
学生查看作业 → 提交作业内容
    │
    ▼
教师查看待批改列表
    │
    ▼
教师打分 + 写评语
    │
    ├──────────────────────────┐
    ▼                          ▼
更新homework_submissions    自动同步到grades表
(score/comment/graded_at)  (exam_type='homework')
    │                          │
    └────────────┬─────────────┘
                 ▼
          成绩管理模块可见
          参与统计分析
```

#### 4.1.2 考试自动阅卷流程

```
教师创建考试 → 启动考试
    │
    ▼
学生登录考试页面 → 答题 → 提交
    │
    ▼
后端接收答案JSON
    │
    ▼
遍历题目，对比正确答案
    │
    ├─ 客观题(单选/判断/多选) → 自动判分 → auto_score
    │
    └─ 主观题 → 等待教师手动打分 → teacher_score
    │
    ▼
最终得分 = auto_score + teacher_score
    │
    ├──────────────────────────┐
    ▼                          ▼
更新exam_submission         自动归档到grades表
(score/auto_score/graded)  (exam_type='exam')
    │
    └────────────┬─────────────┘
                 ▼
          成绩统计分析可用
```

#### 4.1.3 请假审批流程

```
家长提交请假申请
(学生/日期/类型/原因)
    │
    ▼
状态 = pending
    │
    ▼
教师查看待审批列表
    │
    ├─ 批准 → status=approved → 自动同步缺勤记录(records表type=absent)
    │
    └─ 拒绝 → status=rejected → 记录拒绝原因
    │
    ▼
家长查看审批结果
```

#### 4.1.4 上课模式实时互动流程

```
教师选择班级 → 开始上课
    │
    ▼
教师端状态写入localStorage
(classroom_session_{classId})
    │
    ├─ 发布签到 → 学生端轮询检测 → 学生点击签到 → 事件队列 → 教师端处理+积分
    ├─ 发布举手 → 学生端检测 → 学生举手 → 事件队列 → 教师端显示
    ├─ 发布分组 → 学生端检测 → 查看分组信息
    ├─ 发布试题 → 学生端检测 → 答题提交 → 事件队列 → 教师端统计
    ├─ 课堂积分 → 学生端实时查看
    ├─ 排行榜 → 学生端实时查看
    └─ 文件互传 → 教师下发课件/学生提交作业 → 消息通知家长
```

### 4.2 权限控制设计

系统采用基于角色的访问控制（RBAC）：

```
请求到达
    │
    ▼
JwtAuthFilter拦截
    │
    ├─ 验证JWT令牌 → 无效 → 返回401
    │
    └─ 有效 → 解析userId/username/role → 设置request属性
    │
    ▼
Controller层权限校验
    │
    ├─ RoleAccess.isTeacher(req) → 教师/管理员可通过
    ├─ RoleAccess.isAdmin(req) → 仅管理员可通过
    ├─ RoleAccess.isParent(req) → 仅家长可通过
    │
    └─ 权限不足 → 返回403
    │
    ▼
业务逻辑执行
```

### 4.3 密码安全设计

```
用户注册/修改密码
    │
    ▼
BCryptPasswordEncoder.encode(rawPassword)
    │
    ▼
生成$2a$10$开头的哈希值(60字符)
    │
    ▼
存入users.password_hash

用户登录
    │
    ▼
BCryptPasswordEncoder.matches(rawPassword, storedHash)
    │
    ├─ 匹配 → 登录成功 → 生成JWT
    └─ 不匹配 → 密码错误
```

### 4.4 实时消息推送设计（SSE）

```
客户端建立SSE连接
GET /api/message/stream (Authorization: Bearer token)
    │
    ▼
服务端保持连接，每30秒发送心跳注释
    │
    ▼
新消息产生时
    │
    ▼
服务端推送事件: data: {"type":"message","content":...}
    │
    ▼
客户端EventSource接收 → 更新UI(红点/消息列表)
```

## 6. 创新点与特色

### 6.1 教学管理+家校协同+线上测评一体化

传统辅导机构通常使用多个独立工具（微信群沟通、Excel管理成绩、纸质作业），本系统将教学管理、家校沟通、在线测评整合到一个平台，解决多软件切换的痛点，实现数据互通和流程闭环。

### 6.2 基于角色的分级权限管控

系统设计了超级管理员、教师、家长三级角色，实现权责分离和最小权限原则：
- 超级管理员负责系统全局管理，不参与具体教学
- 教师仅能管理所带班级的数据
- 家长仅能查看自家孩子的相关数据
- 所有关键操作记录审计日志，可追溯

### 6.3 教学数据可视化看板

系统集成ECharts数据可视化，提供成绩趋势图、各科平均分柱状图、出勤率/作业提交率/考试通过率等统计指标，辅助机构管理者和教师进行数据驱动的教学决策，体现信管专业"数据驱动管理"的核心思想。

### 6.4 完整的业务流程闭环

系统实现了多个完整的业务闭环：
- **作业闭环**：发布→提交→批改打分→成绩同步→统计分析
- **考试闭环**：组卷→发布→答题→自动阅卷→手动阅卷→成绩归档→数据分析
- **请假闭环**：申请→审批→缺勤同步→记录归档
- **考勤闭环**：发布签到→学生签到→出勤记录→家长查看

### 6.5 上课模式实时互动

上课模式集成了课堂聊天、举手抢答、课堂签到、分组协作、试题分发、课堂积分、排行榜、文件互传等多种实时互动功能，通过localStorage状态共享+轮询机制实现低延迟的师生互动，提升课堂参与度和教学效果。

## 附录：系统部署说明

### 环境要求
- JDK 17+
- MySQL 8.0+
- Maven 3.6+
- 现代浏览器（Chrome/Edge/Firefox）

### 部署步骤
1. 创建数据库 `skt_db`，执行建表SQL
2. 修改 `application.yml` 中的数据库连接配置
3. 执行 `mvn package -DskipTests` 打包
4. 执行 `java -jar target/skt-server-1.0.0.jar` 启动
5. 访问 `http://localhost:8081/tutoring-management.html`

- 超级管理员：admin / admin123（首次登录后建议修改密码）
